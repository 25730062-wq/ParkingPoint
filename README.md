#### v0.6 최종 화면·동작 요약 (수정 16 ZIP 기준)

- 홈: `가장 많이 가는 주차장` 2곳은 실제 방문 순위가 아닌, 표준데이터 483곳에 대해 생성한 시연용 모의 방문 통계로 정렬하며 최대 2곳을 표시합니다. 카드에 가상 방문 횟수와 범위(서울 전체 또는 현재 위치 3/5km 이내)를 안내합니다.
- 탐색/지도: 하단 `탐색` 탭에서 지도와 상단 검색창을 사용합니다. 지도 마커 팝업에는 `상세보기`와 `예약하기`, 우상단 닫기 `×`가 있습니다. 외부 대상의 상세 링크는 내부 상세 페이지가 아닌 카카오 외부 링크를 사용할 수 있습니다.
- 내비게이션: 하단은 `홈 / 탐색 / 마이` 3개만 보이며, 예약 페이지와 예약 완료·상세 등의 기능·파일은 삭제하지 않았습니다.
- 마이페이지: 예약 상태 탭 외에 날짜/주소 검색과 정렬을 제공하고, 카드 전체에서 예약 상세를 엽니다. 취소 시 별도 확인 팝업을 표시합니다. 프로필 옆 로그아웃 버튼은 없고 공통 헤더의 로그아웃 버튼은 유지합니다.
- 예약 완료: 완료 안내에서 바로 `마이페이지에서 내역 보기` 큰 버튼으로 이동합니다. 즐겨찾기·예약 상세 확인 버튼은 이 화면에서 제거되었습니다.
- 검색 대체 경로: 카카오 장소 검색 실패·불가 시 `명동`/`명동역` 참고 좌표 또는 등록 주차장명·주소에 부합하는 데이터의 좌표를 이용해 탐색 위치를 정할 수 있습니다. 이는 정확한 장소 검색 결과나 실시간 API 응답이 아니며, 등록되지 않은 주차장을 신규 생성하지 않습니다.
- 모의 통계 주의: 모의 데이터 파일의 집계 구간은 2026-10-21~2026-11-19입니다. 문서 표기 날짜인 2026-11-16보다 뒤의 날짜도 포함하지만, 가상으로 생성된 값이므로 관측 기록이나 해당 날짜까지의 실제 개발 실적을 의미하지 않습니다.

테스트/검증 상태: 첨부 8개 ZIP의 단계별 차이와 최종 코드의 정적 구조를 확인했습니다. `js/app.js`, `data/parking-data.js`, `data/parking-popularity.mock.js`는 Node.js 구문 검사에 통과했으며 모의 통계는 483개 고유 주차장 ID로 구성된 것을 확인했습니다. 단, 393px 기기 레이아웃·로그인/예약 실제 동작·브라우저 위치 권한·카카오 SDK 및 배포 환경은 실행 검증하지 않았습니다.

- 공통 헤더: 좌측 Parking Point 로고, 우측 인증 상태에 따른 `로그인` 또는 `로그아웃` 글자 버튼. 햄버거 버튼은 상단에서 제거하며, 스크롤 중 헤더 고정 스타일이 적용됩니다. 이전 메뉴 오버레이용 HTML/JS는 다른 기능에 영향이 없도록 그대로 남아 있을 수 있습니다.
- 로그인 화면: 페이지 상단 별도 뒤로 가기·제목 바가 없고 로그인 폼과 보조 동작이 위로 배치됩니다.

#### 5-5. v0.5 시점에 확인된 지도·저장소 적용 상태 (수정9 기준)

- v0.5 기준 `pages/map.html`에는 카카오맵 JavaScript SDK 로더가 포함되어 있으며, `js/app.js`는 SDK 로딩에 성공하면 실제 지도를 생성하고 실패하면 SVG 시연 지도를 남기는 구조입니다. 외부 카카오 API의 실제 응답 성공이나 GitHub Pages 인증 상태는 여기서 검증하지 않았습니다.
- v0.5 기준 코드에서는 카카오 검색 결과를 무제한으로 신규 주차장에 추가하는 것이 아니라 공공데이터에 등록된 대상만 시연용 예약 데이터로 처리하도록 제한하는 로직을 확인했습니다. 앞의 `5-2` 표는 과거 API 연동 설계 설명으로 보존하며, v0.5의 실제 구현 상태는 본 항목을 우선 참고합니다.
- 위치 선택값은 `sessionStorage`의 `pp:location-choice:v1`에, 좌표는 별도의 `pp:position:v3` 값에 저장하도록 작성되어 있습니다. `sessionStorage`는 일반적으로 같은 탭 동안 유지됩니다.
- 비고: 지도 API, 서버 인증, 실제 결제, 실시간 빈자리·실제 예약 동기화는 별도로 검증·구현해야 합니다. 외부 API 키는 이 문서에 기재하지 않습니다.

### 10. 변경 승인 및 추적 규칙

1. 새 기능은 PRD 표에 고유 ID를 기록하고, 구현·테스트 후 상태를 갱신합니다.
