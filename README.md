#### v0.5 최종 화면·동작 요약

- **공통 헤더:** 좌측 Parking Point 로고, 우측 인증 상태에 따른 `로그인` 또는 `로그아웃` **글자 버튼**. 햄버거 버튼은 상단에서 제거하며, 스크롤 중 헤더 고정 스타일이 적용됩니다. 이전 메뉴 오버레이용 HTML/JS는 다른 기능에 영향이 없도록 그대로 남아 있을 수 있습니다.
- **로그인 화면:** 페이지 상단 별도 뒤로 가기·제목 바가 없고 로그인 폼과 보조 동작이 위로 배치됩니다.
- **회원가입 화면:** 페이지 상단 별도 뒤로 가기·제목 바 및 `정보 입력/가입 완료` 단계 표시를 제거합니다. 이메일 → 비밀번호 → 비밀번호 확인 → 닉네임의 기존 입력 구조는 유지합니다.
- **마이페이지:** 별도 제목/뒤로 가기 영역 없이 프로필부터 시작합니다. 로그아웃 상태에서는 예약 영역 내 로그인 유도 **버튼**을 두지 않습니다. 로그인 상태의 예약 필터 첫 항목은 `이용 예정`입니다.
- **홈 위치 요청:** 처음 홈에 들어왔을 때 사용자 정의 위치 선택 창을 표시합니다. `네` 선택 시 브라우저 GPS 권한 요청을 시도하고 결과를 `sessionStorage`에 저장합니다. `아니요` 또는 GPS 사용 불가 시 위치 없이 검색하도록 합니다. **같은 탭에서 저장된 선택이 있을 때는 다시 묻지 않습니다.** 브라우저 자체 위치 권한 안내는 브라우저/기기 설정에 따릅니다.
- **홈 돋보기:** 위치 허용 상태이며 저장된 실제 좌표가 있으면 지도에서 인근 주차장을 탐색합니다. 거부·실패·위치값 부재라면 `pages/reserve.html`의 검색 화면으로 이동합니다. 돋보기를 눌렀다는 이유만으로 별도의 권한 선택 창을 다시 띄우지 않습니다.
- **변경 제외:** 기존 예약 시연, 공공 주차장 데이터, 다른 화면의 콘텐츠와 수치, 지도 API 연동 로직은 이번 v0.5 UI 변경에서 재설계하지 않았습니다.

**테스트/검증 상태:** 위 사항은 제공된 각 단계의 ZIP과 최신 `index.html`·`pages/*.html`·`js/app.js`·`css/style.css` 정적 비교에 근거합니다. **실제 모바일 브라우저의 스크롤, 로그인 전환, 권한 팝업, 지도 API 로딩을 통합 실행해 통과 판정한 것은 아닙니다.**

- 카카오 API 연동 및 홈·지도·마이 UI 재배치는 **별도 변경판**의 내용이며, v0.4 기준 파일에 적용된 것으로 기록하지 않습니다.

- **기준 버전:** 와이어프레임 **v0.4** (`index.html`)를 보존하면서 **현재 변경 이력 및 추가 요구사항은 v0.5**까지 관리합니다.

- **버전별 자료:** `wireframe_version_0.1~0.3.html` / `README_version_0.1~0.3.md`, v0.4는 사용자 제공 기존 `README.md` 기준.

#### 5-5. v0.5 시점에 확인된 지도·저장소 적용 상태 (최신 수정9 ZIP)

- 최신 `pages/map.html`에는 **카카오맵 JavaScript SDK 로더가 포함**되어 있으며, `js/app.js`는 SDK 로딩에 성공하면 실제 지도를 생성하고 실패하면 SVG 시연 지도를 남기는 구조입니다. **외부 카카오 API의 실제 응답 성공이나 GitHub Pages 인증 상태는 여기서 검증하지 않았습니다.**
- 최신 코드에서는 카카오 검색 결과를 무제한으로 신규 주차장에 추가하는 것이 아니라 **공공데이터에 등록된 대상만** 시연용 예약 데이터로 처리하도록 제한하는 로직을 확인했습니다. 앞의 `5-2` 표는 과거 API 연동 설계 설명으로 보존하며, v0.5의 실제 구현 상태는 본 항목을 우선 참고합니다.
- 위치 선택값은 `sessionStorage`의 `pp:location-choice:v1`에, 좌표는 별도의 `pp:position:v3` 값에 저장하도록 작성되어 있습니다. `sessionStorage`는 일반적으로 같은 탭 동안 유지됩니다.
- **비고:** 지도 API, 서버 인증, 실제 결제, 실시간 빈자리·실제 예약 동기화는 별도로 검증·구현해야 합니다. 외부 API 키는 이 문서에 기재하지 않습니다.

### 10. 변경 승인 및 추적 규칙

1. 새 기능은 PRD 표에 고유 ID를 기록하고, 구현·테스트 후 상태를 갱신합니다.
