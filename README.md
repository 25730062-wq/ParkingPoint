### v0.4 — 현재 PRD 기준선

- 사용자가 v0.4로 지정한 `index.html`을 기준으로 홈의 **바로 찾기 / 목적지 검색 / 최근 검색 / 즐겨찾기 / 하단 내비게이션**을 관리합니다.
- 지도·주차장 상세·예약·마이·인증 화면 및 브라우저 기반 시연 흐름을 현재 범위로 기술합니다. 구체적 구현/실행 상태는 v0.4 소스와 브라우저에서 확인합니다.
- 카카오 API 연동 및 홈·지도·마이 UI 재배치는 **별도 변경판**의 내용이며, v0.4 기준 파일에 적용된 것으로 기록하지 않습니다.

### v0.3 — 서울시 주차장 표준데이터로 교체

- **HTML 변경:** `script src="data/mock-data.js"` → `script src="data/parking-data.js"`; 상단 브랜드 `Mock 서비스` → `서울시 주차장 표준데이터`; 하단 주의 문구를 `실시간 빈자리와 실제 예약 가능 여부는 제공되지 않으며 예약은 시연용`으로 교체했습니다.
- **데이터:** 사용자 제공 `서울시주차장정보표준데이터.json` **483건**을 원본으로, `parking-data.js`를 브라우저 실행용 변환 데이터로 사용합니다. 원본 변경 시 변환 파일 재생성이 필요합니다.
- **유지된 구조:** 홈의 바로 찾기·검색·최근 검색·즐겨찾기·하단 메뉴 및 공통 오버레이 구조는 v0.2와 대체로 동일합니다.
- **제약:** 실시간 잔여 주차면과 실제 예약 API는 없습니다.

### v0.2 — 다중 화면 및 예약 시연 구조로 확장

- **홈 HTML 변경:** 가까운 주차장 찾기가 목적지 검색보다 위로 이동, 공통 헤더의 햄버거 버튼(`data-action="menu"`)과 전체 메뉴 오버레이(`menuOverlay`) 추가. `body`에 `data-page="home"`, `data-prefix=""` 설정.
- **데이터 연결:** `data/mock-data.js`와 `js/app.js`를 불러오는 구조. 위치·잔여면수·요금이 가상 Mock 데이터임을 안내합니다.
- **페이지 연결:** 하단 `지도/예약/마이` 및 전체 메뉴에서 `pages/map.html`, `pages/reserve.html`, `pages/my.html`, 로그인·회원가입·즐겨찾기 등으로 연결합니다.
- **README에 설명된 기능:** 시연용 SVG 지도/마커·정렬·필터, 상세 정보·즐겨찾기, 로그인/회원가입, 예약 단계·중복 확인·예상 요금, 완료/예약 상세/현장 이용, 마이페이지 조회·취소.
- **HTML-first 전환:** JS `innerHTML`로 본문을 생성하던 방식에서 `index.html` 및 `pages/*.html`에 마크업을 직접 작성하는 방식으로 전환했습니다. (해당 README 안의 `v4` 표현은 첨부 파일 버전 v0.2로 분류)
- **제약:** 서버 인증·실제 지도 API·실시간 주차 정보·실제 결제 없음. 계정 및 예약은 브라우저 로컬 저장소에서만 관리합니다.

### v0.1 — 홈 중심 와이어프레임 및 검색 경험

- **홈 UI:** 상단 로고/제목, 목적지 검색 입력창, `주차장 찾기` 버튼, 가까운 주차장 바로 찾기 버튼, 즐겨찾기 미리보기, 하단 `홈/지도/예약/마이` 항목.
- **위치 기반 검색:** GPS 위치와 Mock 주차장 좌표의 **직선거리**를 계산해 잔여 면수 1면 이상인 가장 가까운 주차장 한 곳을 표시합니다. (도로/도보 거리 아님)
- **최근 검색:** 최근 검색어 최대 5개를 `localStorage`에 저장하고 재검색·개별 삭제·전체 삭제를 지원합니다.
- **제약:** 가상 주차장 데이터 사용. 지도·예약·마이페이지는 미구현이며 하단 항목은 미구현 안내용 버튼입니다.

## PRD — 제품 요구사항 정의서 (와이어프레임 v0.4 기준)

### 1. 제품 개요

**제품명:** Parking Point  
**제품 형태:** 서울시 주차장 표준데이터를 이용한 모바일 중심 웹 서비스(시연용).  
**목표:** 사용자가 목적지나 현재 위치를 기준으로 주차장을 찾고, 위치·운영시간·기본 요금 정보를 살펴본 뒤 예약 과정을 체험할 수 있도록 한다.  
**기준 화면:** `index.html` (와이어프레임 v0.4).  
**지원 형태:** 모바일 우선 UI.

### 2. 사용자 및 핵심 사용 시나리오

- **주요 사용자:** 서울에서 주차 위치를 검색하거나 주차장 정보를 비교하려는 운전자.
- **시나리오 A — 목적지 검색:** 홈 검색창에 지역·주차장 검색어 입력 → 지도/검색 결과 → 주차장 상세 확인.
- **시나리오 B — 현재 위치:** 홈의 가장 가까운 주차장 찾기 → 브라우저 위치 권한 처리 → 주변 주차장 탐색.
- **시나리오 C — 예약 시연:** 지도·상세에서 주차장 선택 → 날짜·시간·주차면 선택 → 예약자 정보 입력 → 시연용 예약 내역 조회/취소.
- **시나리오 D — 재방문:** 최근 검색·즐겨찾기·마이페이지에서 이전 선택을 재사용.

### 5. 데이터 정리 (JSON · API · 저장소)

#### 5-1. 데이터 소스 목록

| 구분 | 이름 / 파일 | 형식 | 용도 | v0.4 상태 |
|---|---|---|---|---|
| 원본 데이터 | `서울시주차장정보표준데이터.json` | JSON (483건) | 서울시 공영·민영 주차장 원본 정보 | 사용 |
| 변환 데이터 | `data/parking-data.js` | JS (JSON 변환) | 브라우저에서 바로 불러오기 위한 변환본 | 사용 |
| 이전 데이터 | `data/mock-data.js` | JS (가상 데이터) | v0.2까지 사용한 시연용 Mock | v0.3에서 교체 |
| 외부 API | 카카오맵 지도 / 장소 검색 API | JavaScript SDK | JSON에 없는 주차장의 위치 정보, 실제 지도 표시 | v0.4 미반영 (별도 API 연동판) |

#### 5-2. 데이터 역할 분담 (API 연동판 기준)

| 구분 | JSON 주차장 | 카카오 API 주차장 |
|---|---|---|
| 출처 표기 | **J** | **A** |
| 제공 정보 | 이름, 주소, 좌표, 전체 주차면, 운영시간, 요금 | 장소명, 주소, 좌표 |
| 예약 시연 | 가능 | 위치 정보 표시 위주 |
| 표시 위치 | 지도 핀, 주변 주차장 목록 | 지도 핀, 주변 주차장 목록 |

- 주변 주차장 목록에는 각 주차장의 데이터 출처(**J** = JSON / **A** = API)를 함께 표시합니다.
- 카카오 API 사용 시 GitHub Pages 배포 도메인을 카카오 개발자 콘솔의 허용 도메인에 등록해야 합니다. API 키는 문서에 기재하지 않습니다.

#### 5-3. 주요 데이터 필드 (JSON)

주차장명, 도로명/지번주소, 위도·경도, 전체 주차면, 운영일·운영시간, 기본/추가 요금 등.

#### 5-4. 데이터 제한

- 실시간 잔여 주차면, 실제 예약 가능 여부, 결제 승인·실제 예약 처리는 제공되지 않습니다.
- 값이 없는 요금·운영정보는 실제 사실로 추정하지 않습니다.
- 실제 검색 노출 건수는 `parking-data.js`의 변환·필터 조건에 따라 483건과 다를 수 있습니다.
- 원본 JSON이 바뀌면 `parking-data.js`를 다시 생성해야 합니다.

### 6. 생성형 AI 도구 활용

### 7. 비기능 요구사항

| ID | 요구사항 | 검증 기준 |
|---|---|---|
| NFR-01 | 모바일 중심 레이아웃 | 모바일 폭에서 주요 검색·예약 버튼을 조작할 수 있고 가로 넘침이 없다 |
| NFR-02 | 내비게이션 일관성 | 홈/지도/예약/마이 하단 메뉴와 전체 메뉴가 각 페이지에서 올바르게 연결된다 |
| NFR-03 | 접근성 기본 준수 | 폼의 레이블, 버튼 접근 이름, 키보드 조작 및 상태 메시지를 점검한다 |
| NFR-04 | 오류 상태 안내 | 위치 권한 거부, 검색 결과 없음, 필수 정보 누락 상황을 설명한다 |
| NFR-05 | 개인정보·안전한 시연 | 서버 인증 또는 실제 결제 기능으로 오해시키지 않으며 실제 비밀번호 사용을 권하지 않는다 |
| NFR-06 | 정적 호스팅 | 상대 경로를 유지하여 로컬 정적 서버 및 GitHub Pages에서 핵심 화면이 열리도록 한다 |

### 8. 화면별 수용 테스트

- [ ] 홈: 검색어 입력 → 지도 결과로 이동, 최근 검색 기록 확인
- [ ] 홈: 현재 위치 허용/거부 각각의 화면 흐름 확인
- [ ] 지도: 주차장 핀·목록 클릭 → 상세 또는 예약 화면 이동
- [ ] 지도: 거리순/요금순 정렬 및 검색 결과 없음 메시지 확인
- [ ] 예약: 유효한 날짜·시간·주차면 선택과 필수 입력 검증
- [ ] 마이페이지: 생성한 시연 예약의 확인·취소·완료 화면 이동

- [ ] 모바일: 화면 폭 393px 기준 헤더, 하단 탭, 지도·예약 영역 넘침 확인
- [ ] 배포: GitHub Pages에서 상대 경로 및 브라우저 콘솔 오류 확인

### 10. 변경 승인 및 추적 규칙

1. 새 기능은 PRD 표에 고유 ID를 기록하고, 구현·테스트 후 상태를 갱신합니다.
2. 배포 ZIP이 달라지면 기준 버전과 사용한 `index.html`을 명시합니다.
3. 변경 이력에는 버전, 날짜, 변경 내역, 확인 근거를 남기고 최신 기록을 위에 추가합니다.
4. 구현하지 않은 기능은 `계획` 또는 `미검증`으로 표기합니다.
5. 주차장 원본 데이터와 API 키 등은 임의 수정하거나 노출하지 않습니다.
